# 老旧 Android 专用媒体桌面设计规格

日期：2026-10-29  
状态：用户已确认，进入实施

## 1. 产品目标

把闲置的 Android 手机和平板改造成无广告、无账号依赖、触控优先的专用媒体设备。用户无需 root、无需刷机，也不需要停用系统组件；安装后可将应用选择为默认 HOME 桌面，开机和按 Home 键均回到媒体桌面。

首版最低支持 Android 6.0（API 23）。应用保留 Wi-Fi、移动数据、蓝牙、音量、电源和系统设置能力，并能启动网易云音乐、QQ 音乐、小宇宙等官方应用。

## 2. 已确认的产品决策

- 采用“轻量专机模式”，不使用强制 kiosk、Device Owner 或 Lock Task。
- 不 root、不刷机、不停用或卸载系统应用。
- 官方流媒体内容由各平台官方 App 播放；本项目不重做登录、会员、版权或 DRM 能力。
- 首版最低系统为 Android 6.0（API 23）。
- 竖屏使用“播放优先”布局；横屏使用“环境时钟优先”布局。
- 横竖屏共用相同播放会话，旋转时不得停止或重新开始音频。
- 所有用户数据默认仅保存在本机；不加入广告、账号系统或遥测。

## 3. 范围拆分

当前版本只实施媒体桌面 MVP。本地音乐、RSS 播客和网络电台属于未来候选能力，不进入首版实施计划，也不在首版界面中展示未完成入口。

### 里程碑 1：媒体桌面 MVP

本轮实施范围：

- 可被选择为默认 HOME 的媒体桌面。
- 首次设置与恢复原桌面指引。
- 检测并启动网易云音乐、QQ 音乐和小宇宙官方 App。
- 允许用户从已安装应用中添加其他媒体 App。
- 显示网络、电量和时间状态。
- 提供 Wi-Fi、移动网络、蓝牙、音量、应用管理和系统设置入口。
- 用户主动授予通知使用权后，读取兼容 App 的 MediaSession，并显示曲名、作者、封面、播放状态及基础控制。
- 竖屏播放优先、横屏环境时钟优先的响应式首页。
- 在 Xiaomi MIX 2S 实机完成安装、默认桌面、官方 App 启动和旋转验证。

### 未来候选：本地音乐

- 通过 MediaStore 扫描本地音频。
- 按歌曲、专辑、艺术家和文件夹浏览。
- 后台播放、播放队列、断点续播和耳机控制。

### 未来候选：RSS 播客

- RSS/Atom 订阅、OPML 导入导出。
- 单集流式播放、下载、倍速、断点续播和定时停止。

### 未来候选：网络电台

- 用户自行添加合法的 HTTP/HTTPS 电台地址。
- 收藏、最近播放和断线重连。

### 明确不在首版范围

- 本地音乐扫描与原生播放。
- RSS/Atom 播客订阅、下载与播放。
- 网络电台收藏与播放。
- 逆向网易云、QQ 音乐或小宇宙私有接口。
- 替第三方应用保存账号、Cookie 或令牌。
- 下载或分发第三方 APK。
- 影视聚合、IPTV 搜索、弹幕或视频资源站。
- ADB debloat、系统包停用和厂商机型清理清单。
- 云同步、多用户、远程管理和 Web 管理后台。
- Android 5.x 兼容版。

## 4. 技术架构

### 4.1 技术选型

- Kotlin。
- 原生 Android View/XML 布局，使用 `layout` 与 `layout-land` 实现双方向界面。
- 不使用 WebView、Flutter 或 React Native。
- 最低 API 23；编译与目标 SDK 使用开发时稳定版本。
- 首版不引入 Media3；使用系统 `MediaSessionManager`/`MediaController` 读取和控制外部会话。未来开发原生播放器时再独立评估并引入 Media3。
- SharedPreferences 保存首版轻量配置；只有未来确需管理本地媒体或播客数据时才评估 Room。

选择 View/XML 而不是 Compose，是为了降低首屏启动、内存和依赖成本，并简化 1–2 GB RAM 旧设备上的性能验证。

### 4.2 模块边界

#### Launcher Shell

职责：处理 HOME Intent、首页生命周期、方向切换和系统返回行为。它不直接了解具体流媒体平台协议。

#### App Catalog

职责：枚举可启动应用、识别预置官方媒体包、维护用户白名单并安全启动目标 Activity。Android 11 及以上只通过清单中的显式 `<queries>` 和 LAUNCHER Intent 查询必要应用，不请求广泛包可见性。未安装的预置 App 不出现在媒体源列表（2026-10-30 起不再显示缺失卡片），也不在桌面占位。

#### External Playback Bridge

职责：在用户授予通知使用权后获取活跃 MediaSession，将元数据和播放能力转换成统一的只读 UI 状态，并向兼容会话发送播放、暂停、上一首和下一首命令。可用性以系统“已启用的通知监听组件授权”为准，不要求监听服务处于绑定状态（2026-10-30 修复 MIUI 更新后不同步的问题）。

#### System Gateway

职责：读取时间、电量和连接状态；通过标准 Intent 打开网络、蓝牙、音量、应用管理、默认应用和系统设置。它不尝试静默切换移动数据或修改受保护系统设置。

#### Local Settings

职责：保存媒体 App 白名单、首页排序、是否显示状态项、方向偏好和新手引导完成状态。

各模块通过明确的数据模型通信，不直接引用对方的 Activity 或内部存储实现。

## 5. 界面与交互

### 5.1 竖屏：播放优先

- 顶部显示时间、日期、Wi-Fi/移动网络和电量。
- 中部优先显示当前封面、标题、作者/来源及播放控制。
- 下方只保留一个紧凑的媒体源图标（显示最近使用/当前媒体 App 的图标）；点击后在弹窗中切换设备已安装的媒体 App，不显示尚未开发的本地音乐、播客或电台入口。
- 没有活跃播放会话时，封面区域显示安静的空状态，而不是推荐内容或广告。

### 5.2 横屏：时钟 + 封面模式

- 左侧显示大时钟、日期、网络与电量（2026-10-30 起不再显示固定文案）。
- 右侧显示放大的播放封面、标题、作者与进度。
- 播放/上一首/下一首固定在屏幕底部居中；媒体源图标在左下，设置在右下。
- 没有活跃播放时，右侧显示空状态与最近使用的媒体入口，不从网络抓取推荐内容。
- 歌词：Android `MediaSession` 不提供歌词文本接口，本项目也不读取通知正文或逆向第三方私有接口，因此 0.1 不做歌词模式；未来本地音乐播放器或用户提供的 LRC 字幕再扩展。

### 5.3 方向与状态连续性

- 默认跟随系统自动旋转，不强制锁定方向。
- 设置页允许用户固定竖屏、固定横屏或跟随系统。
- Activity 重建后从 ViewModel/保存状态恢复当前 UI；实际播放由外部官方 App 或后续独立播放服务持有，因此旋转不能打断音频。

### 5.4 安全出口

设置入口不得被主题或排序隐藏。设置页固定提供：

- 打开系统网络与蓝牙设置。
- 打开默认应用/HOME 设置。
- 切换回原系统桌面的说明。
- 打开本项目应用详情或卸载页。
- 清除本项目本地配置。

### 5.5 媒体源入口（2026-10-30 变更）

2026-10-30 根据实际使用反馈调整：首页不再显示官方/附加媒体 App 卡片行，改为一个 56 dp 的媒体源图标入口（无障碍最小触控目标）。

- 图标显示当前选中的媒体 App 图标；未选择过时回退到第一个已安装的官方媒体 App；没有任何已安装媒体 App 时显示通用音符图标。
- 点击图标弹出“选择媒体应用”对话框，只列出设备上已安装的媒体源（官方 App 优先，其后是用户在设置中添加的附加应用），当前来源标记“当前”。
- 选择一项后启动对应官方 App，并把该包名记为最近使用的媒体源，图标同步更新。
- 未安装的官方 App 不再在桌面占位；设置页仍保留“附加媒体应用”管理入口。
- 首页空状态文案相应改为“点击下方音乐图标，开始聆听”。

### 5.6 横屏封面模式与移除固定文案（2026-10-30 变更）

- 移除横屏电量下方的固定文案“留一点时间，慢慢听”，并删除设置页对应开关；该内容对实际使用没有价值。
- 横屏改为封面模式：左侧时钟/日期/设备状态，右侧放大封面 + 标题/作者/进度，播放控制固定在屏幕底部；媒体源与设置入口保持在左右下角。
- 未实现歌词模式：系统 MediaSession 不暴露歌词数据，读取第三方通知内容或私有接口超出项目边界（且与隐私原则冲突）。歌词能力留待本地音乐/LRC 里程碑评估。

### 5.7 封面全屏背景（2026-10-30 变更）

- 有播放封面时，封面同时作为整个媒体桌面的全屏背景：`centerCrop` 铺满，叠在黑色窗口之上，透明度 30%，保证白色/灰色文字与状态仍满足对比度。
- 不引入模糊、渐变、视差或动画；背景复用播放桥已按 512 px 上限缩放的同一张位图，不额外解码、不写磁盘、不长期缓存。
- 无播放或会话不提供封面时，背景保持纯黑，不显示占位图或伪造图案。
- 竖屏与横屏使用同一规则；横屏的封面卡片仍保留，用于承载标题/作者/进度的视觉焦点。

### 5.8 隐藏系统状态栏（2026-10-30 变更）

- 默认隐藏系统状态栏（时间、通知图标等）；桌面自身已显示时间、日期、网络与电量，隐藏后更像专注的媒体设备。
- 设置页“外观与屏幕”提供“隐藏系统状态栏”开关，默认开启；关闭后恢复系统状态栏。
- 隐藏时采用 transient-by-swipe：从屏幕顶部下滑可临时唤出状态栏与通知，随后自动隐藏；不隐藏导航栏，返回/主屏/最近任务仍可用，安全出口不丢失。
- 只作用于媒体桌面 Activity，其他应用不受影响；不改变系统权限与通知使用权。

### 5.9 Walkman 风格视觉（2026-10-30 变更）

- 视觉方向：Sony Walkman 致敬（现代简化版）——近黑底、暖白细字、单一琥珀强调色、方形封面、圆形描边控制按钮。
- 时钟使用 `sans-serif-light` 并加大字号；日期/设备状态使用小字距与 muted 灰；标题/作者保持 18sp 以上的可读层级。
- 播放控制、媒体源、设置入口统一为描边/圆形样式；播放控制与媒体源按钮为 56dp，设置入口为图标按钮（48dp 视觉、56dp 触控代理、不显示文字）；进度条改为 4dp 细线（琥珀填充、深灰底槽）。
- 设置页动作按钮改为描边样式，主操作（恢复系统桌面）仍使用琥珀实心强调；不引入品牌 logo、拟物材质、模糊或动画。
- 与封面全屏背景、隐藏状态栏、双方向布局兼容。

## 6. 数据流

### 6.1 启动官方 App

1. App Catalog 查询目标包及可启动 Activity。
2. 已安装且可启动时，Launcher Shell 发出显式启动 Intent。
3. 未安装时不出现在媒体源弹窗中；不崩溃，也不自动下载 APK。
4. 用户按 Home 键返回媒体桌面。

### 6.2 外部正在播放

1. 用户在引导页主动开启通知使用权。
2. External Playback Bridge 订阅活跃 MediaSession 列表。
3. 选取当前正在播放或最近活跃的媒体会话。
4. 将元数据、状态和可用操作映射为首页状态。
5. 控制按钮只发送会话明确支持的命令；不支持的按钮隐藏或禁用。

### 6.3 系统设置

1. 用户点击网络、蓝牙或系统设置。
2. System Gateway 使用公开系统 Intent。
3. Intent 不可解析时显示明确错误，不尝试厂商私有组件或提权操作。

## 7. 权限与隐私

里程碑 1 仅使用实现功能必需的能力：

- `ACCESS_NETWORK_STATE`：显示当前网络状态。
- Notification Listener：不是普通运行时权限，必须由用户在系统页面明确开启；拒绝后官方 App 仍可正常启动，只是不显示统一正在播放卡片。

里程碑 1 不申请通知发送、通讯录、短信、电话、位置、相机、麦克风或存储权限。Android 会把 Notification Listener 描述为可访问通知内容，因此授权页必须明确解释这一系统能力；本项目不得解析、记录或传输通知正文，只使用该授权调用 `MediaSessionManager.getActiveSessions()`，并只处理 MediaSession 暴露的播放元数据。用户可随时关闭该授权，桌面随即降级为应用启动器。

## 8. 错误与降级策略

- 默认 HOME 未设置：应用仍可作为普通 App 打开，并显示完成设置的入口。
- 官方 App 未安装：不出现在媒体源弹窗中，不崩溃、不自动下载 APK（2026-10-30 起不再显示缺失卡片）。
- 官方 App 无可启动 Activity：显示“当前版本不可启动”，提供应用详情入口。
- 通知使用权未授予：显示简化的媒体入口，隐藏跨 App 播放控制。
- MediaSession 缺少封面或字段：使用来源 App 图标与可用文本，不伪造元数据。
- 会话不支持上一首/下一首：对应按钮隐藏或禁用。
- 网络断开：官方 App 启动不受阻；首页只显示离线状态，不循环弹窗。
- 系统设置 Intent 不存在：显示一次性说明和应用详情入口。
- 发生未捕获异常：下一次启动仍应进入安全首页，不能形成 HOME 崩溃循环。

## 9. 性能预算

里程碑 1 的目标预算：

- 无活跃播放时不运行持续轮询。
- 不使用视频背景、模糊、粒子动画或远程壁纸；播放封面可作为全屏背景，但必须复用内存中的封面位图、不做模糊/动画，并用暗化透明度保证文字对比度。
- 封面图片按显示尺寸采样，并设置内存缓存上限。
- 冷启动到可操作首页以 MIX 2S 为首个基准，后续在 1–2 GB RAM 设备或等效模拟环境复测。
- 后台不自建常驻服务；MediaSession 监听跟随桌面可见性和系统许可。
- 进度条在播放且桌面可见时按 1 秒本地插值推进（使用已上报的 position + 已过时间，不轮询 MediaSession）；暂停、离开桌面或进程停止时立即停止推进，新的状态上报会重新校准位置。

## 10. 验证计划

### 自动化测试

- App Catalog：包存在、缺失、不可启动和用户白名单排序。
- External Playback Bridge：完整元数据、缺失字段、不同能力集合和会话切换。
- System Gateway：Intent 可解析与不可解析。
- 首页状态：无播放、有播放、离线和权限拒绝。
- 方向切换：状态保存与恢复。

### MIX 2S 实机验收

- 安装后可作为普通 App 打开。
- 用户可选择其为默认 HOME，按 Home 键稳定返回。
- 网易云音乐 9.6.15 可启动并正常使用 Wi-Fi/移动数据。
- 在授权通知使用权后，验证网易云音乐是否暴露 MediaSession；若暴露，验证元数据和基础控制。
- 未安装 QQ 音乐、小宇宙时不出现在媒体源列表，桌面不出现空位或错误状态。
- 竖屏与横屏切换不打断正在播放的音频。
- 网络、蓝牙、应用详情和默认桌面设置入口可用。
- 切回 MIUI 原桌面后设备恢复正常使用。
- 重启后不会进入崩溃循环。

### 后续兼容矩阵

至少增加：Android 6/7 的 32 位 ARM 环境、1–2 GB RAM 环境、一台非 MIUI 设备和一台平板尺寸设备。

## 11. 首台设备基线

- Xiaomi MIX 2S（`polaris`）。
- Android 10 / API 29，MIUI 12.5。
- Snapdragon 845，arm64，约 6 GB RAM。
- 1080 × 2160，440 dpi。
- 当前默认桌面：MIUI Home。
- 已安装网易云音乐 9.6.15（该版本 `minSdk 23`）；QQ 音乐和小宇宙未安装。

该设备用于首轮开发与 MIUI 验证，但不代表低内存性能下限。

## 12. 完成标准

首版只有在自动化测试通过、MIX 2S 实机验收全部完成、恢复原桌面路径验证成功，并且不存在 HOME 崩溃循环时，才能称为完成。本地音乐、RSS 播客和网络电台不属于首版完成条件。
